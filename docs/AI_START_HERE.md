# AI 共创入口

本项目由人主导目标、产品取舍、思路与工作流程，由 AI 参与代码、测试、工具和文档开发。我们特别欢迎贡献者使用自己的 AI 编程助手一起共建；无需使用某一种模型、购买指定服务或取得原作者的聊天记录。AI 参与本身不是质量证明，提交者仍需理解改动并对证据负责。

## 第一次接手

1. 读取仓库根目录 `AGENTS.md`，它是所有 AI 工具共用的项目约束。
2. 读取 [交接快照](HANDOFF.md)，确认版本、已完成项、禁用路径与验收缺口。
3. 读取 [贡献指南](../CONTRIBUTING.md) 和 [架构](ARCHITECTURE.md)，按所选问题继续读取相关代码与证据；不要从长篇路线图第一版重新研究。
4. 在 [共建任务](COMMUNITY_TASKS.md) 选择一个有明确验收条件的小任务，检查 GitHub 是否已有相关 Issue/PR。
5. 先运行离线基线，再实施单一改动。没有游戏环境时，可贡献文档、纯领域逻辑和离线测试，明确保留实机门禁。

不要求安装作者个人 Skill。若某个工具提到本机专用 Skill，而贡献者没有它，使用仓库内的贡献、安全和验证规则；不要伪称已读取，也不要依赖作者电脑的路径或凭据。

## 可复制给 AI 的开场提示词

```text
请协助我参与 MHRise Monster Coach 共建。人负责目标、范围与验收判断，AI 负责协助分析、实现和验证。
先读取 AGENTS.md、docs/AI_START_HERE.md、docs/HANDOFF.md、CONTRIBUTING.md；
再读取本次任务涉及的架构、代码和 docs/evidence。核对当前分支、HEAD 与工作树，保留已有改动。
本次任务：<填入 Issue 链接或明确目标>。
我的环境：<Windows/PowerShell/Python；是否有游戏与对应 REFramework；没有则写没有>。
先总结目标、已有证据、未知项、预计修改文件与最小验收方案，然后在这个范围内推进。
保持 MVC 和逐怪 Profile 边界，禁止解锁已知崩溃路径、用观察频次证明固定派生、用无伤证明反击成功。
默认只做离线工作。部署、启动游戏、注入输入、写游戏状态和发布须在本次明确授权范围内。
不要从旧版本重新研究，也不要把静态测试或工具调用成功写成实机已通过。
结束时报告改动、命令及结果、未验证部分和后续接手点，准备小范围 PR。
```

## 每轮留下什么

- 人确认的任务目标和范围；重要路线变化的理由。
- 使用的 AI 工具/模型（可选提供版本），以及人类实际审核了什么。
- 可公开的验证命令、结果摘要、源码提交和运行时基线。
- 明确的失败结论和停止条件，避免下一位 AI 重走已否定路线。
- 未完成项；不要为了收尾把 `candidate`、`research_only` 或未知项改成已验证。

无需公开私有聊天、隐藏推理、账号信息、原始游戏资源或存档。用可复现决策摘要替代聊天全文。
