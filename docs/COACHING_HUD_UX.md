# 场上出招提示体验契约

## Experience Brief

- 目标用户：正在观察怪物起手、判断派生并练习应对的单人猎人。
- 核心任务：默认只用一行醒目文字确认“怪物正在出什么招”；需要研究派生或复盘时，再主动开启详细陪练 HUD。
- 完成证据：招式切换后的下一渲染帧内，屏幕上方中央出现独立预警；招式结束且没有辅助状态时自动安静下来。
- 视觉关系：不再绘制卡片或边框；使用亮色大字、深色偏移阴影和青色“陪练预警”标签，在复杂场景中保持辨识度，同时明确表示这是 Mod 信息。
- 信息层级：`简洁招式提示`只显示招式名，默认开启且可拖动；`详细陪练 HUD`保留阶段、派生、通用应对、可选武器应对、单轮复盘和训练进度，默认关闭。

## State & Interaction Matrix

| 状态 | 主预警 | 辅助卡片 | 不应出现 |
|---|---|---|---|
| 无已知招式 | 隐藏 | 没有临时状态时隐藏 | 标题、目标 ID、按键帮助 |
| 已知招式 | 仅显示招式名 | 仅在详细 HUD 开启时显示当前可用信息 | Action ID、State key、动画帧 |
| 有固定派生 | 保持当前招式 | `固定派生` | 把条件或随机结果说成固定 |
| 有条件派生 | 保持当前招式 | `条件派生`及条件 | 虚假的唯一后继 |
| 有随机/观测候选 | 保持当前招式 | `随机候选`或`观测候选` | 伪确定性结论 |
| 子弹时间生效 | 保持当前招式 | 临时显示倍率 | 常驻 F6 帮助 |
| 指定起手训练中 | 保持当前招式 | 一行训练状态与轮次 | 实际 FSM 路径调试串 |
| 完成单轮 | 当前招式照常 | 一行语义复盘 | 原始命中事件和内部计数 |

## 交互审查

普通菜单顶层保留：总启用、场上提示、默认开启的简洁招式提示、默认关闭的详细陪练 HUD、手动子弹时间、指定起手训练、玩家和怪物训练保护、子弹时间倍率、F7 原生任务重开。派生、通用应对、可选武器应对和单轮复盘只在详细 HUD 开启后展开。

“调整出招提示位置”开启后，仅在 REFramework 菜单可见时创建与实际文字范围一致的透明拖动区域；释放鼠标时把屏幕比例坐标写入配置。关闭后不创建交互窗口、不占用战斗鼠标。没有当前招式时显示位置预览，“恢复默认位置”回到屏幕上方中央。

以下入口不再占用普通操作路径：

- “显示招式”不再单独提供。招式名是场上提示的核心内容，关闭整个场上提示即可隐藏。
- F8 记录锚点与 F9 原地复位不再展示。它们无法重建区域、环境生物和完整世界状态，且已有崩溃证据。
- 实验手柄组合开关不再展示。当前键位可能与游戏动作冲突，待形成可配置语义输入后再进入产品界面。
- 判定体绘制、导出校准证据和重载静态 AI 归入折叠的“开发诊断”。
- 目标检测、运行时版本、Action Reader、State key、动画进度、装备识别、Hitbox 计数和实际 FSM 路径只属于诊断面板，不得进入场上 HUD。

## Acceptance Gate

- 简洁招式提示不得绘制背景矩形或边框；详细陪练 HUD 保留独立背景与边框，关闭时不得绘制或留下空白占位。
- 简洁与详细模式必须支持四种开关组合，默认组合严格为“简洁开、详细关”。
- 实机训练验收必须在同一轮中先记录默认简洁布局，再自动开启并记录详细布局，结束后恢复用户原配置；不得把模式切换和重复测试转交给玩家。
- 主招式字体必须使用单独测量的较大 CJK 字体；加载失败时安全回退到正文字体。
- 640×360 与 1920×1080 都不得越过屏幕底部或内容宽度。
- 空闲状态不绘制常驻标题、状态或按键说明。
- 拖动位置必须使用归一化坐标、约束在屏幕内，并且只在释放时请求一次持久化。
- 条件、随机、观测和待确认派生必须使用不同文案。
- 增加第二只及后续怪物时只提供数据，不得复制或分叉 HUD 代码。
