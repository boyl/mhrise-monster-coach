# 单轮事件复盘体验契约

## Experience Brief

目标用户是在高失败成本下反复练习怪物关键起手的猎人。核心任务是：一次应对结束后，无需离开战斗视线，即可确认刚才招式的有效判定窗口与本轮结果。入口是场上 Overlay 的“单轮复盘”开关；完成证据是一行包含招式、判定窗口和文字结果的摘要；关闭该开关即可退出，不改变任何训练或游戏状态。

详细应对继续由 `Response` 提供，复盘行不重复长说明。当前版本只显示具有明确来源和证据等级的猎人动作语义；防御、回避等尚无精确语义来源的状态不进入结果分类，社区来源的见切/居合节点明确标为候选。只读模式下未观察到受击不会被解释为成功。

`outcome_classifier.lua` 是 Model 内的纯领域分类边界。输入仅为当前轮结构化事件、是否启用生命追踪和累计伤害；输出稳定的 `outcome / score / label / tone / reason / evidence`，不读取 REFramework 对象也不绘制 UI。判定优先级为：明确受击 → 已验证成功节点 → 生命追踪下的无伤 → 未验证成功候选节点 → 尝试节点 → 未分类。社区候选成功节点只能显示“候选”，不能累计语义反击成功；生命追踪的无伤仍可用于既有轮次统计，但明确显示“应对方式待确认”。

轮询得到的 `ActStatus.Guard / Escape / Damage` 以 `player_status` 事件进入同一时间轴，保留采样时刻、怪物阶段和怪物动画帧。状态转换去重：中立状态不产生噪声，进入与退出活动状态各记录一次，新怪物 Action 会重新建立边界。`Damage` 是明确受击证据；`Guard` 和 `Escape` 只能证明玩家执行了防御/回避动作，缺少格挡命中或无敌帧重叠证据时分别显示“防御尝试/回避尝试”，不得计为语义成功。

分类结果同时携带结构化 `timing`：优先使用受击事件相对已确认判定窗的 `before/inside/after`，否则使用玩家应对采样时的怪物阶段及距离下一/上一判定的帧数。View 只显示“判定前 N 帧、判定中、判定后 N 帧”；只有动作发生在已结束的收招阶段时追加“可能偏晚”。前摇阶段在没有武器专属成功窗模型时不武断标记“过早”。

## State & Interaction Matrix

| 状态 | 触发 | 可见反馈 | 允许操作 | 保留/清理 |
|---|---|---|---|---|
| 空 | 尚无完整 Action | 不显示复盘行 | 正常战斗、关闭开关 | 无临时复盘 |
| 记录中 | 当前 Action 尚未结束 | 继续显示上一完整轮，不闪烁半成品 | 正常战斗 | 当前事件仅留在 Model |
| 已完成 | Action 切换 | `复盘: 招式｜判定｜结果` | 正常战斗、重置、关闭开关 | 保留最近一轮 |
| 只读未分类 | 未启用可靠结果追踪且未观察到受击 | 明文显示“结果待分类” | 正常战斗 | 不累计成功 |
| 应对尝试 | 观察到见切/居合等尝试节点，但没有已验证成功节点 | 显示“已尝试…，结果待确认” | 正常战斗 | 不累计语义成功 |
| 成功候选 | 观察到社区来源的成功候选节点 | 显示“观察到…成功候选节点” | 正常战斗 | 不累计语义成功 |
| 已验证反击 | 观察到本运行时已验收的精确成功节点且本轮未受击 | 显示具体动作成功 | 正常战斗 | 可累计成功 |
| 事件溢出 | 单轮超过事件上限 | 明文追加“事件不完整” | 正常战斗 | 保留最近事件与丢弃计数 |
| 已关闭 | 菜单关闭“单轮复盘” | 不显示复盘行 | 可重新开启 | Model 证据不删除 |

复盘没有独立键位和焦点，不与 F6/F7/F8/F9 或手柄快捷键竞争。View 按时间轴修订号更新一次只读快照，同一轮后续渲染复用摘要。

## Acceptance Gate

- 受击、无伤、只读受击和未分类均用文字表达，不只依赖颜色。
- 多段判定最多展开前两段，其余显示段数；事件缺失必须明示。
- 640×360 内容宽度下所有行通过当前字体实测收进面板；1920×1080 下完整摘要可见。
- 中文字体仍复用现有加载、已加载状态和样本文本宽度门禁；字体测量不可用时退回既有字符上限。
- 重置清除未完成轮但保留上一完整轮；离开任务不产生伪造结果。
- 此门禁目前仅完成离线自动测试，真实分辨率、UI 缩放、窗口/全屏和超宽屏必须等用户允许部署后集中验收。

训练场景终态报告由 `tools/analyze_training_timeline_acceptance.py` 自动复核。完整门禁要求：轮次全部完成、时间轴 schema 3、单轮事件无丢失且序号连续、首尾分别为 `action_start/result`、至少一组有序 `hitbox_open/hitbox_close`、结果由 `behavior_tree_attack_exit` 结算，以及结果分类与原始事件一致。结构错误进入 `invalid_training_timeline`；仅缺判定窗或强退出证据时降级为 `verified_partial_training_timeline`，不得伪装成完整验收。

历史实机报告已用于回归：咆哮 5/5 被识别为完整时间轴和 `observed_failure`，仍保持不可计分；右回旋的完整判定窗报告被识别为完整时间轴但结果 `unclassified`，因此不会被升级为成功。旧版缺失时间轴或仍处于 active 的报告会失败关闭。报告哈希和精确输出见 [`docs/evidence/TRAINING_TIMELINE_ANALYZER_ACCEPTANCE_2026-08-30.json`](evidence/TRAINING_TIMELINE_ANALYZER_ACCEPTANCE_2026-08-30.json)。

`0.49.38` 为开发验收增加可选的玩家应对侧车，不改变产品训练输入。首个契约只允许 `tigrex_rotate_attack_right_single + dodge + 1`：外部工具在活动轮唯一 Action 26 起点后最多发送一次由 `snow.StmInputConfig` 只读解析出的闪避键；侧车记录轮次、动作序号、键位来源、发送结果和失焦策略。分析器只有在同一终态轮观察到 `player_status.escape=true` 时才把响应标为 `verified`；“操作系统接受输入”本身不能通过门禁。
