# 指定起手训练菜单体验契约

## Experience Brief

- 目标用户：需要低成本反复练习轰龙关键起手与真实派生的单人猎人。
- 唯一核心任务：查看一个起手的派生树，确认有效轮数，开始训练，并在完成或失败后明确选择再练、换招或 F7 安全重开。
- 入口：`REFramework → Script Generated UI → Monster Coach → Specified Move / 指定出招`。
- 完成证据：训练向导显示“本轮完成”，并保留当前选择、完成轮数、实际路径和结果时间轴。
- 退出路径：执行中点击“停止训练”；怪物状态异常时按 F7；关闭“指定出招训练”会立即取消排队或执行中的训练。
- 恢复原则：起手选择与派生预览保留，临时请求、行为树采样和输入所有权清除；不会因重进菜单自动再次发送 Action 请求。

## State & Interaction Matrix

| 状态 | 触发 | 可见反馈 | 允许操作 | 保留与清理 |
|---|---|---|---|---|
| 未启用 | 功能开关关闭 | 说明启用后才能开始 | 查看派生树、启用功能 | 保留选择；关闭瞬间取消活动训练 |
| 当前不可用 | 联机、不支持版本、非目标任务、怪物未加载，或上次请求因运行时条件取消 | 显示具体原因和进入条件 | 查看派生树、返回任务流程；范围已恢复且保留选择时可明确重试 | 不自动发送请求；保留选择 |
| 暂无可用起手 | 数据包没有 `verified` 场景 | 解释未验证 Action 不会开放 | 返回、等待数据包更新 | 无执行入口 |
| 请选择起手 | 范围就绪但尚未预览 | 引导选择“查看派生树” | 选择起手、调整轮数 | 不创建训练轮 |
| 可开始 | 已预览一个已验证起手 | 当前选择、简介、派生树、有效轮数和限制原因 | 开始当前起手、换起手、调轮数 | 保留选择和预览 |
| 准备/请求/站位/训练中 | Controller 正在执行训练生命周期 | 单一状态标签、进度和当前选择 | 仅停止训练或 F7；目录与轮数锁定 | 结束前不允许切换起手或重复提交 |
| 本轮完成 | 达到目标轮数 | 完成状态和结果 | 再练一次、换起手 | 保留选择；清除活动请求 |
| 训练失败 | 请求、派生或退出合同失败 | 原因、重新尝试和 F7 回退说明 | 重新尝试、换起手、F7 | 不自动重试；保留已收集证据 |
| 已停止 | 用户停止或关闭功能 | 明确已停止 | 继续当前起手或换起手 | 清除活动跟踪；保留选择 |

输入焦点仍由 REFramework Script Generated UI 管理。本阶段不新增原始键值或手柄映射；菜单业务只接收查看、开始、停止、次数选择和开关语义。执行中锁定目录和次数，避免同一点击既切换选择又触发旧场景。

## Acceptance Gate

- 普通 UI 与开发探针必须消费同一个 `training_menu_view_model`，不得分别推断状态。
- 只有 `verification.status == verified` 的场景进入目录；候选和未知 Action 不显示为可执行项。
- 开始按钮必须同时满足：显式启用、单人目标任务、轰龙已加载、已查看派生树、当前无活动训练。
- 执行中只显示一个停止入口；不显示开始、切换或轮数按钮。
- 成功、失败和停止均保留当前选择；失败不会自动重试。
- 联机、版本不支持、错误任务和未加载怪物分别显示具体原因，不能合并为“不可用”。
- 关闭功能必须立即取消排队/执行状态；再次启用后不得自动恢复旧请求。
- 最低宽度下按钮使用“开始当前起手 / 再练一次 / 重新尝试”短标签，招式名称在独立选择标题中显示，不把长名称重复塞进按钮。
- 离线状态与 ImGui 渲染契约测试必须全通过；下一次集中部署只需抓取一份完整菜单快照，不重复 8 项动作和结果门禁。
- `run_probe_session.ps1 -UiContract` 必须自动调用 `analyze_training_menu_contract.py`；目录重复、派生树缺失、次数门禁漂移或状态按钮所有权冲突都会使该次探针失败。
