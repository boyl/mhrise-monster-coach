# 怪物陪练开发路线图

本文件记录完整目标、当前状态和解锁门禁。功能不会因为当前不可用而被删除；未通过安全验证的能力保持锁定，并显示具体原因。

## 状态定义

- `已验证`：自动测试和对应实机门禁均通过。
- `候选`：代码已实现、自动测试通过，仍需一次集中实机验收。
- `开发中`：契约或实现正在推进，不对用户宣称可用。
- `待解锁`：设计保留，但依赖安全写入、完整数据或前置功能。

## 当前推进批次

唯一当前主线是“可信阶段解析”：

1. 从运行时活动 Hitbox 的开启/关闭边沿提取有效判定窗口，不用统一百分比或损坏的 MOTLIST 结果猜测。
2. 将窗口绑定到 `ActionCategory + ActionNo + Motion`，防止复用动作误配。
3. 用安全模式自动采集的真实受击帧交叉验证。
4. 只有 `confirmed` 窗口才能驱动居合、见切、刚·气刃斩或追击推荐；其余保持通用回避。
5. 一次集中部署和实机验收后，再进入子弹时间与原地重置写入阶段。

## 长期不变量

- Steam PC、单人训练；多人时写入能力全部禁用。
- 不修改存档、奖励、正式任务装备或联机数据。
- 静态名称和 AI 结构优先从成熟数据源离线导入；游戏运行时只读取必须实时变化的状态。
- 未知、随机、条件和固定派生必须显式区分。
- 每只怪物的数据独立版本化；通用代码不写死轰龙 Action ID。
- 所有游戏状态写入都必须有退出、异常和重开恢复路径。
