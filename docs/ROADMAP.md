# 怪物陪练开发路线图

本文件记录完整目标、当前状态和解锁门禁。功能不会因为当前不可用而被删除；未通过安全验证的能力保持锁定，并显示具体原因。

## 状态定义

- `已验证`：自动测试和对应实机门禁均通过。
- `候选`：代码已实现、自动测试通过，仍需一次集中实机验收。
- `开发中`：契约或实现正在推进，不对用户宣称可用。
- `待解锁`：设计保留，但依赖安全写入、完整数据或前置功能。
- `不开发`：明确保留在路线图中，但不进入当前或可预见批次；只有重新评估条件满足后才能改回候选。

## 推荐实施顺序

1. 完成轰龙实用版：覆盖最值得练习的 8–12 个起手及主要固定、条件和随机派生。
2. 完成训练结果分类：受击、防御、回避、见切、居合与反击。
3. 完成判定与输入事件时间轴，用结构化事件解释“早了、晚了、方向错误或资源不足”。
4. 扩展更多武器的专属应对数据包。
5. 在轰龙闭环稳定后扩展第二只复杂怪物，验证多怪物架构。

“仅怪物减速实验模式”和“真正的视频或世界状态回放”不属于上述实施序列，不得在核心闭环完成前消耗开发与验收预算。

## 明确保留但不开发

### 仅怪物减速实验模式

当前决策：`不开发`。以下内容仅保存未来重新评估时必须满足的完整性门禁，不代表已经排期：

- 与全局子弹时间分开配置，不互相覆盖。
- 全局子弹时间用于保持猎人与怪物的真实速度比例，只延长现实思考时间。
- 仅怪物减速用于观察前摇、判定和派生；必须醒目标注“不代表正常速度下的真实应对窗口”。
- 怪物动画、AI Action/FSM、根运动、物理位移、转向、攻击判定、怪物投射物和派生计时必须使用同一倍率。
- 任一子系统无法同步时，该怪物或该招式保持不可用，不允许以视觉减速冒充完整实现。
- 退出任务、切换怪物、进入多人、脚本异常或关闭功能时，所有倍率和临时状态必须恢复。

### 真正的视频或世界状态回放

当前决策：`不开发`。

- 正式替代方案是“判定与输入事件时间轴”，记录 Action/FSM、Motion 帧、判定窗口、玩家关键输入、结果和派生转换。
- 不自行录制长视频，不把视频文件管理、编码和回放 UI 纳入 Mod 核心。
- 不通过批量写回 Transform、生命、AI、碰撞体、投射物、环境生物或任务对象模拟世界快照。
- 只有发现游戏或 RE Engine 已存在可调用的原生 Replay/SaveState 生命周期，并证明能完整重建上述状态、隔离正式存档且连续运行无崩溃时，才允许重新立项。
