# 怪物陪练开发路线图

本文件记录完整目标、当前状态和解锁门禁。功能不会因为当前不可用而被删除；未通过安全验证的能力保持锁定，并显示具体原因。

## 状态定义

- `已验证`：自动测试和对应实机门禁均通过。
- `候选`：代码已实现、自动测试通过，仍需一次集中实机验收。
- `开发中`：契约或实现正在推进，不对用户宣称可用。
- `待解锁`：设计保留，但依赖安全写入、完整数据或前置功能。

## 当前推进批次

当前主线已由“逐项强制 Action”收敛为“指定起手、原生续接、实时派生训练”。首个用户入口“执行：咆哮”已在 `0.33.0-specified-move-training` 由用户实机确认，`0.34.0-repeat-training` 又通过真实 Controller 自动完成 3/3 循环；小咬扩充仅完成 1/3 后出现 Action 不退出，证明一次注入成功不能代表可重复训练，入口已撤回。下一批先建立稳定空闲入口和 `native_branch` 路径追踪，再选择一个具有明确派生的根动作验证，后续不逐个强塞 Action。直接局内重置仍只接受引擎原生重建/重置接口，不恢复已证明会崩溃的 Transform 写回路径。古塔准备区到战斗区已采用坐标导航、一次性交互和战斗层判定自动完成，开发探针可在单项异常后通过 F7 恢复并继续采样。

`0.34.3` 的自动批量探针进一步否定了“由静态 Action 边直接挑根动作”的捷径：Action 15 和 18 的真实退出均为 category 1/action 8，而不是静态图的 category 4/action 2；Action 16 进入 `TigDashLoop_New` 后未在 900 帧内退出并被自动恢复。因此下一步不扩大 Action ID 白名单，改为寻找能保留 Think/Combo/FSM 上下文的高层入口；在找到安全写入口前，运行时自然选中根动作的只读追踪可先用于验证派生树。

`0.36.0` 的 3600 帧自然行为调查记录了 20 个 FSM 节点、31 条边，并观察到 `BiteHookHalfTurnStartShortRange (Action 5000) -> BiteHookHalfTurnAttackNormal (Action 5001)`。随后仅注入一次 5000、完全不写后继的对照实验却转入 `Move.Dash`，证明 Action 请求会丢失原生 Think/FSM 分支上下文。该候选不进入用户菜单；下一阶段限定为寻找高层 Think/FSM 激活入口或可自动构造的原生条件诱导，独立单招路径与原生派生路径从此分开验收。

开发验收器已能自动启动游戏、选择首个存档、进入离线大厅、直接接取固定陪练任务、等待任务稳定、执行一次 F7 完整重开并核对重新进入。任务接取阶段不再依赖窗口焦点或菜单按键；外部按键桥仅用于标题页和存档页。环境生物自动验收默认仅做只读观察，主动生成候选因当前运行时容器不兼容且曾触发原生崩溃而保持关闭。

`tools/audit_coaching_coverage.py` 将怪物静态数据包与实机校准证据合并审计，统一列出已见招式的名称、应对、可靠阶段和派生缺口。当前轰龙报告保存在 `docs/evidence/TIGREX_COACHING_COVERAGE.json`：18 个已见攻击均有名称和应对，14 个已有重复或确认的判定阶段，严格固定派生仍只保留 3 个来源动作。

古塔 Map 14 的公开地图坐标来自 MHRice，原生 `QuestAreaMovePopMarker` 的精确位置由运行时焦点事件交叉确认并固化为静态默认数据；新安装无需再做首次盲扫。区域枚举在该地图不一致，因此战斗区门禁使用猎人与目标怪物的实时垂直层差。完整坐标、传送和强制动作证据见 `docs/evidence/ARENA_NAVIGATION_AND_FORCED_ACTION_2026-08-22.json`。

## 长期不变量

- Steam PC、单人训练；多人时写入能力全部禁用。
- 不修改存档、奖励、正式任务装备或联机数据。
- 静态名称和 AI 结构优先从成熟数据源离线导入；游戏运行时只读取必须实时变化的状态。
- 未知、随机、条件和固定派生必须显式区分。
- 每只怪物的数据独立版本化；通用代码不写死轰龙 Action ID。
- 所有游戏状态写入都必须有退出、异常和重开恢复路径。

## 仅怪物减速

- 与全局子弹时间分开配置，不互相覆盖。
- 全局子弹时间用于保持猎人与怪物的真实速度比例，只延长现实思考时间。
- 仅怪物减速用于观察前摇、判定和派生；必须醒目标注“不代表正常速度下的真实应对窗口”。
- 怪物动画、AI Action/FSM、根运动、物理位移、转向、攻击判定、怪物投射物和派生计时必须使用同一倍率。
- 任一子系统无法同步时，该怪物或该招式保持不可用，不允许以视觉减速冒充完整实现。
- 退出任务、切换怪物、进入多人、脚本异常或关闭功能时，所有倍率和临时状态必须恢复。
